# UX Outline — CS Newsletter
## Cloud Code Skill · Owner: Daniela Cavalcante

---

## Purpose

This skill defines the **user experience structure, layout rules, and design principles** for the CS Newsletter — a self-service Customer Success tool that helps marketplace sellers stay educated and up to date with hyperscaler changes.

Use this skill when generating, updating, or reviewing any newsletter layout, section structure, or onboarding flow. This skill works alongside:
- `topic-discovery.md` (Gelo Baring) — defines *what* content to surface
- `writing-guide.md` (Dia Mercado) — defines *how* content is written (tone, voice, style)

---

## Product context

The newsletter is a hybrid between a **knowledge base** and **product marketing**. It serves two personas at different levels of marketplace maturity. Content is AI-generated via an automated pipeline and split 50/50 between:
1. **Recency updates** — what changed this week (tracked, timestamped)
2. **Educational deep dives** — derived from the Universal Guide (static curriculum)

---

## Personas

### The Explorer
- **Profile:** Curious, building a mental map of the marketplace. Low familiarity with policies, co-selling, and hyperscaler dynamics — but motivated to learn.
- **Primary need:** Orientation, context, and a clear starting path. Wants to understand before acting.
- **Content they should see:** Universal Guide sections, 30/60/90 day curriculum, policy definitions, marketplace fundamentals.
- **UX priority:** Simplicity, progressive disclosure, no jargon. "What to do first" framing. Education leads the feed.

### The Tracker
- **Profile:** Already active in the marketplace. Plugged in, focused on signals. Needs to know what moved and why.
- **Primary need:** Recency — what changed, when, and how it affects them. Acts fast on new information.
- **Content they should see:** Documentation diffs, new feature announcements, tax/region updates, co-sell news, relevancy-scored items.
- **UX priority:** Information density, visible timestamps, domain filters, clear "new" vs "updated" signals. Updates lead the feed.

## Core UX rules

These rules must be respected in every layout generated by Cloud Code.

### 1. Two-click rule
Every persona must reach their relevant content in **at most 2 clicks** from the home screen. Do not bury persona-specific content behind more than one navigation layer.

### 2. Persona filter persistence
The selected persona (Explorer or Tracker) must persist throughout the session. Always display the active filter state visibly in the header or navigation bar.

### 3. Scannable cards
Every content card must follow this format:
- Domain badge (e.g. `Marketplace`, `Co-sell`, `Cloud`)
- Persona badge (`Explorer` or `Tracker`)
- Title (max 10 words)
- Preview text (max 3 lines / ~150 characters)
- Timestamp (for recency items) or section tag (for guide items)
- Relevancy score (visible for Tracker persona; optional for Explorer)

### 4. Timestamps on all recency items
Every item in the "What Changed" section must display:
- Date of change (e.g. `May 6, 2025`)
- Status label: `NEW` or `UPDATED`
- Source reference (e.g. `AWS Marketplace docs`)

### 5. No clutter
Avoid mixing Explorer and Tracker content in the same feed without clear visual separation. When both personas are shown together, use a visible divider or badge system. When filtered, show only the relevant persona's content.

### 6. Export support
Every view must support export to HTML and print-to-PDF. Maintain clean print styles: remove navigation elements, preserve content hierarchy, include timestamps in footers.

## Page / section structure

### Onboarding screen (first visit)
Shown once. Collects:
- Name (optional)
- Company (optional)
- Persona selection: **Explorer — I'm building my foundation** / **Tracker — I'm already active in the marketplace**

The selected persona personalizes the default feed. Users can change it at any time in settings or the header.

### Home — Newsletter feed

```
┌─────────────────────────────────────────────┐
│  Header: Edition title · Date · Level filter │
│  [101]  [201]  [All]                         │
├─────────────────────────────────────────────┤
│  SECTION 1 — WHAT CHANGED THIS WEEK         │
│  ┌──────────────────────────────────────┐   │
│  │ [Marketplace] [NEW] May 6            │   │
│  │ Title of the update                  │   │
│  │ Short preview text...                │   │
│  │ Relevancy score ●●●○○               │   │
│  └──────────────────────────────────────┘   │
│  (repeat card pattern)                       │
├─────────────────────────────────────────────┤
│  SECTION 2 — DEEP DIVE                      │
│  Featured article or guide section           │
│  [Read more →]                               │
├─────────────────────────────────────────────┤
│  QUICK LINKS                                 │
│  Universal Guide · Documentation · Next steps│
└─────────────────────────────────────────────┘
```

**Section 1 — What Changed (50% of content)**
- Cards ordered by recency (most recent first)
- Each card: domain badge, status badge, timestamp, title, preview, relevancy score
- Filter bar: `All` / `Marketplace` / `Co-sell` / `Cloud`
- Tracker persona sees this section first; for Explorer persona it appears second

**Section 2 — Deep Dive (50% of content)**
- 1 featured article or Universal Guide section per edition
- Educational framing: "This week's concept", "From the guide", etc.
- CTA: "Read full guide section →"
- For Explorer persona: this section appears first

**Quick links**
- Link to Universal Guide (filtered by persona level)
- Link to current week's documentation changes
- Suggested next action for the week

### Universal Guide (always accessible)

- Accessible from main navigation at all times
- Organized by topic → level → section
- Navigation tree (left sidebar or accordion):
  - Marketplace 101
  - Co-selling
  - Cloud market fundamentals
  - Policy & compliance
- Each section shows: last reviewed date, level badge, estimated read time
- Explorer persona lands here on first visit if they selected that persona

## Navigation rules

| Element | Behavior |
|---|---|
| Persona filter (Explorer / Tracker / All) | Persistent in header. Always visible. |
| Domain filter (Marketplace / Co-sell / Cloud) | Available in Section 1 only. Resets on page reload. |
| Back navigation | Always present on detail pages. Returns to feed at last scroll position. |
| Universal Guide link | Always in main navigation. Never buried. |
| Export button | Present on all content pages. |

## Visual hierarchy guidelines

Use these when generating HTML or component layouts:

1. **Section headers** — uppercase label + subtle divider line. E.g. `WHAT CHANGED THIS WEEK`
2. **Badges** — small pill labels. Use color to encode domain (not persona). Persona badge uses a neutral style (`Explorer` / `Tracker`).
3. **Timestamps** — muted, small (12px), placed below the title or in the card footer
4. **Relevancy score** — 5-dot visual indicator. Show for 201 persona by default.
5. **CTAs** — single primary action per card. Avoid competing links.
6. **Spacing** — generous whitespace between sections. Cards should breathe, not stack tight.

## Onboarding flow (step by step)

```
Step 1: Welcome screen
  → "Welcome to the CS Marketplace Newsletter"
  → Brief value prop (2 sentences max)
  → [Get started →]

Step 2: Persona selection
  → "How do you approach the marketplace?"
  → [Explorer — I'm building my foundation]
  → [Tracker — I'm already active, I need to stay current]

Step 3: Personalized feed
  → Redirect to home with persona pre-applied
  → First-time tooltip: "Your feed is set for [Explorer / Tracker]. Change anytime."
```

Onboarding must not require login or account creation. Persona selection is stored in local session/cookie only.

---

## Export behavior

When the user triggers export or print:
- Hide: navigation bars, filter controls, badges that are UI-only
- Show: all content, timestamps, source links, edition date in footer
- PDF footer format: `CS Newsletter · [Edition date] · [Section name]`
- HTML export: self-contained single file with inline styles

## Integration with pipeline

This UX outline is used by Cloud Code to:
1. Generate newsletter HTML structure with correct section order per persona
2. Place content cards in the correct section based on type (`news` vs `deep-dive`)
3. Apply persona badges (`Explorer` / `Tracker`) and visibility rules automatically
4. Render the onboarding screen on first load
5. Apply export styles when generating HTML/PDF output

When receiving content from the topic discovery agent (Gelo), map:
- `type: "news"` → Section 1 (What Changed)
- `type: "deep-dive"` → Section 2 (Deep Dive)
- `persona: "explorer"` or `"tracker"` → apply persona badge and visibility rule
- `recency_score` → render as 5-dot relevancy indicator

When receiving tone/style from the writing guide (Dia), apply at the card preview and article body level. Section headers and navigation labels follow this UX outline, not the writing guide.
